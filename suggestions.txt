TULOY: SUGGESTIONS
==================

Everything I can think of that would make Tuloy better: more accurate, more
efficient, friendlier, nicer to live with, and more presentable. 170 items.
This is the full list; it includes the ideas from helpideas.txt, so that
file can go if you'd like one list.

How to read it

  [H] [M] [L]   how much it would help: high, medium, low
  (S) (M) (L)   how big the job is: an hour or two, about a day, several days

Numbers are just names, so you can say "do 3, 14 and 41". Nothing here is
built yet.


WHAT YOUR REAL PINGS SHOWED
---------------------------

Tuloy has now sent real pings on your Mac (read from its saved history on
6 October). These facts shaped the list:

  - Signing in from the Connection screen worked. Every ping since has
    got through.
  - Each ping used 350 tokens. That is the whole cost, and nearly all of
    it is what Claude Code adds by itself, not the "hi".
  - Every ping came back with an exact reset time AND a percentage, for
    both the 5-hour window and the week. So Tuloy does get true usage from
    a ping. The trouble is only how rarely it asks.
  - Reset times were all on 10-minute marks: 4:40, 10:00, 3:00, 8:00. A ping
    sent at 10:01:12 gave a reset of exactly 3:00:00 PM, so Claude rounds a
    window's start down, to 10 minutes or to the hour. Four pings can't say
    which.
  - Keep going works: scheduled ping at 5:00, then 10:01 and 3:01 by itself.
  - Before sign-in, Tuloy retried a ping that could not work 8 times.
  - The usage on screen can be hours old. A ping at the start of a window
    reads 0%, and nothing updates it until the next ping 5 hours later.

A. ACCURATE USAGE AND TIMES
---------------------------

1.  [H] (M) Check usage without spending tokens.
    Claude Code has a /usage command that may run without a conversation.
    If "claude -p /usage" really costs nothing, run it every few minutes
    and the ring is always true, wherever you use Claude. Needs one test in
    Terminal first: does it print percentages, and are the tokens zero?

2.  [H] (S) Show how old the reading is.
    "62% used · 4 min ago" on Home, the mini window and the menu. Fade the
    ring when the reading is more than 15 minutes old, so an old number
    never passes for a current one.

3.  [H] (S) A Refresh button next to the usage.
    One click to update now, by whatever means item 1 settles on. Until
    then it can say plainly: "Refreshing sends one ping (350 tokens)."

4.  [M] (S) Refresh when you look.
    Opening the Tuloy window or the menu is a good moment to update, if the
    reading is older than a few minutes and it costs nothing.

5.  [H] (S) Step the time picker to match Claude's rounding.
    Windows start on 10-minute marks at least, maybe on the hour. Offer
    times in those steps so the time you pick is the time you get. Decide
    which after a week of pings (see 6).

6.  [M] (S) Learn the rounding from real pings.
    Keep each ping's send time and reported reset. After a dozen, Tuloy can
    say for certain whether it's 10 minutes or the hour, and tell you.

7.  [M] (S) Say when the plan and the truth differ.
    If you asked for 10:00 and Claude reports 10:40 (because a window was
    already open), say so on Home: "Today's fresh window is 10:40, not
    10:00, because a window was already running."

8.  [M] (M) Notice windows you opened yourself.
    If you use Claude before the ping, a window opens and Tuloy doesn't
    know until its own ping. A free usage check (1) would catch it and
    correct "next fresh window" straight away.

9.  [M] (S) Show the week as clearly as the window.
    The weekly figure arrives with every ping. Give it its own small ring
    or bar on Home instead of a line of text.

10. [M] (M) A weekly forecast.
    "At this pace your week runs out Wednesday afternoon." Uses the weekly
    percentages Tuloy already collects.

11. [L] (S) Drop "about" once it isn't needed.
    Real pings always report a reset time, so the estimate path is now rare.
    Keep it, but log when it happens: it would mean Claude Code changed.

12. [L] (S) Count down in seconds for the last minute.
    The countdown jumps from "1m" to "<1m". For the last minute, tick every
    second so the reset feels exact.

13. [L] (S) Tick on the minute.
    The 30-second loop starts whenever Tuloy starts, so "3:12" can change
    at :17 past. Line it up with the clock so times change when the minute
    does.


B. EFFICIENCY
-------------

14. [H] (S) Stop retrying when only you can fix it.
    Signed out, not installed, wrong account: retrying can't help. Wait for
    the free sign-in check to pass, then ping once. This would have saved 8
    pointless attempts (24 program launches) on your first day.

15. [H] (S) Remember which ping flags work.
    Each failed ping runs the lean command, then the plain one, then the
    sign-in check. Once the lean one has worked, don't try the plain one
    again unless the error really is "unknown option".

16. [M] (S) Remember where claude is.
    Tuloy looks for the command before every ping and every check. Find it
    once and keep it, looking again only if it stops working.

17. [M] (M) Find out what the 350 tokens are.
    Record input, cached and output tokens separately for each ping. Then
    try the flags that might trim Claude Code's own overhead, one at a time,
    and keep whichever lowers the count.

18. [M] (S) Check sign-in less often.
    Every time a Tuloy window comes to the front, it runs the sign-in check.
    Do it only while a step is unfinished, or at most once a minute.

19. [M] (S) Draw the menu bar ring only when it changes.
    The ring image is redrawn on every refresh. Keep the last one and
    redraw only when the number or the fill changes.

20. [M] (M) Sleep until something can happen.
    Checking every 30 seconds is cheap, but most of the day nothing is due.
    With no window on screen, wake at the next ping time and on wake-from-
    sleep, and let macOS rest the app in between.

21. [L] (S) A shorter ping time limit.
    A ping takes a few seconds. The 90-second limit could be 45, so a stuck
    one is noticed sooner.

22. [L] (S) Show what pings cost in a day and a week.
    "Tuloy used 1,050 tokens today." Proof, in the app, that it's small.

23. [L] (M) Read ping output without tying up threads.
    The code that collects a command's output holds two worker threads for
    the length of the ping. A lighter way exists.

24. [L] (S) Keep history in a file, not in preferences.
    Twenty pings fit in preferences. A year of them, for charts, belongs in
    a small file in ~/.tuloy.


C. RELIABILITY
--------------

25. [H] (S) A morning health check.
    Run the free sign-in check an hour before the scheduled ping. If it
    fails, notify then, while there's time to fix it.

26. [H] (S) Say when Claude Code updated.
    Remember Claude Code's version at each good ping. If pings start failing
    right after it changes: "This began when Claude Code updated to 2.2.0."

27. [M] (S) Say when a ping went out late.
    "Today's ping went out at 8:02 instead of 5:00 (your Mac was asleep), so
    your fresh window is 1:02 PM." Today it is silent.

28. [M] (S) Nudge after three missed mornings.
    If the scheduled ping is missed three days running, suggest the iPhone
    Shortcut once. Not again after that.

29. [M] (S) Show launch-at-login trouble.
    macOS can refuse or ask for approval. Preferences should say "Approve
    Tuloy in System Settings > Login Items" with a button that opens it.

30. [M] (S) Show when notifications are blocked.
    If macOS has notifications off for Tuloy, say so beside the toggle,
    with a button to System Settings.

31. [M] (M) A plain log file.
    One line per event in ~/.tuloy/tuloy.log: pings, checks, wake-ups,
    files changed. The first thing to look at when something seems wrong.

32. [L] (S) Two Macs.
    Two Macs running Tuloy both ping. Harmless, but say so in Help and
    suggest running it on one.


D. FIRST RUN AND CONNECTING
---------------------------

33. [H] (S) Notice a finished sign-in without a click.
    After Sign In…, check every few seconds while Terminal is in front, so
    the step turns green the moment you finish, before you even switch back.

34. [H] (M) Sign in without Terminal.
    Run Claude Code's sign-in from inside Tuloy and just open the browser
    page. No Terminal window at all. Needs testing: the sign-in may want a
    real terminal.

35. [H] (S) Say the surprising thing first.
    Most people will be signed in to the Claude app and expect that to be
    enough. Put "Claude Code needs its own sign-in" on the welcome's first
    connect line, not in the step's small print.

36. [M] (S) Tidy up after sign-in.
    Delete "Sign in to Claude Code.command" from ~/.tuloy once the check
    passes. It is still sitting there now.

37. [M] (S) Show the exact command before the first ping.
    In the welcome: "This is everything Tuloy will ever send," with the
    command, before anyone presses Send Test Ping.

38. [M] (M) One-click install of Claude Code.
    A button that runs the official installer and shows its progress, for
    people who have never opened Terminal.

39. [M] (S) Suggest a fresh time in the welcome.
    Instead of an empty picker: "Most people pick two to three hours after
    they start. Start at 8? Try 10:30."

40. [M] (S) Let people skip the welcome.
    A "Skip" link on every page, for those who know what they're doing.

41. [M] (S) Celebrate the first good ping.
    A clear, happy moment when the test ping works: a big tick, "You're
    connected," and what happens next.

42. [L] (S) Choose which claude to use.
    For people with more than one installed: pick the path in Connection.

43. [L] (M) A short tour.
    Three pointers on first open: the menu bar icon, Ping Now, the mini
    window. For people who skip the welcome.

44. [L] (S) Explain the plan badge.
    Connection says "Claude Pro plan". Add a line on what that means for
    limits, or a link to Anthropic's page about them.


E. HOME AND THE MAIN WINDOW
---------------------------

45. [H] (S) A "what just happened" line after every action.
    After Ping Now, Pause, or a schedule change, one sentence where you're
    looking: "Pinged. Fresh window at 8:00 PM." No wondering whether a
    click did anything.

46. [H] (M) Today's real windows on Home.
    The picture of the day only shows the plan. Put the real day on Home:
    the windows that actually opened, a "now" line, and what's still to
    come. It answers "where am I?" at a glance.

47. [H] (S) Say why the next ping is when it is.
    "Next ping 8:01 PM, when this window ends (keep going)" instead of only
    a time.

48. [M] (S) Fold repeated failures into one line.
    Eight "signed out" lines in a row could be "8 failed tries, 4:42 to
    7:43 PM: Claude Code was signed out."

49. [M] (S) A full history screen.
    Home shows five pings. Add "Show all", grouped by day, with a filter for
    failures.

50. [M] (S) Click a ping for its details.
    Reset time, tokens, how long it took, which command was used, and the
    raw error if it failed.

51. [M] (S) A progress spinner while pinging.
    "Pinging…" text alone is easy to miss. Show a small spinner on the
    button and the ring.

52. [M] (S) Let the window resize.
    It is a fixed size. Let it grow, and remember its size and place.

53. [M] (S) Remember the last screen.
    Reopen on whichever screen you were last on, unless something needs
    fixing, in which case open Connection.

54. [M] (S) Hover help everywhere.
    A short tooltip on every button and number, in the same plain words as
    Help.

55. [M] (S) A (?) beside each setting.
    Opens the matching Help answer, instead of making people go and look.

56. [M] (S) An About screen.
    Version, what Tuloy is in two lines, "not made by Anthropic", and where
    to send feedback.

57. [L] (S) Show the version in the sidebar.
    Small, under the status dot. Handy when asking for help.

58. [L] (S) Undo for Pause.
    Pausing by accident stops everything quietly. A "Paused. Undo" line for
    a few seconds would catch it.

59. [L] (S) Friendlier empty states.
    "No pings yet" could say when the first one will go out and offer a
    test ping right there.

60. [L] (M) A "This week" screen.
    Each day's windows, how full they got, and pings sent: one place to see
    whether the schedule suits you.

61. [L] (S) Copy details for support.
    One button that copies Claude Code's version, the last five pings and
    your settings (never your login) for pasting into a message.


F. MENU BAR AND MINI WINDOW
---------------------------

62. [H] (M) A proper popover under the menu bar icon.
    Replace the plain text menu with a small panel like the mini window:
    the ring, the countdown, big Ping Now and Pause buttons.

63. [H] (S) A Dock icon while a window is open.
    Tuloy has no Dock icon, so its windows hide behind others and don't
    appear when switching apps. Show one while the main window is open.

64. [M] (S) Remember where the mini window was.
    And reopen it there. Today it returns to the top right.

65. [M] (S) Mini window sizes.
    Tiny (ring only), normal, and wide (with the week). Pick in
    Preferences or by a right-click.

66. [M] (S) See-through until hovered.
    The mini window at 60% until the mouse is over it, so it's there
    without being in the way.

67. [M] (S) Right-click menu on the mini window.
    Ping Now, Pause, size, "this desktop only", close.

68. [M] (S) Choose what the menu bar shows.
    Beyond the four looks: percent as plain text, time left as text, or
    both side by side.

69. [M] (S) Colour as a warning.
    Turn the menu bar ring orange above 80% and red above 95%, as the big
    ring already does.

70. [L] (S) A keyboard shortcut for Ping Now.
    System-wide, chosen in Preferences.

71. [L] (S) A shortcut to show and hide the mini window.

72. [L] (S) Shorter menu.
    With a popover (62) most menu lines can go. Until then, group the
    status lines under one heading.

73. [L] (L) A desktop widget.
    The ring and countdown as a macOS widget. Needs a widget extension, so
    a real Xcode project.

--------------------------

74. [H] (M) Suggest a fresh time from how you work.
    "Your windows usually open around 9:10. A fresh window at 11:00 would
    suit you." Worked out from real history.

75. [M] (M) Different times on different days.
    Early on weekdays, late on Saturday.

76. [M] (S) Skip a day.
    "Skip tomorrow" or "Skip until Monday" without touching the schedule.

77. [M] (S) Pause until.
    "Pause for 2 hours" or "until tomorrow", instead of a pause you must
    remember to undo.

78. [M] (S) Explain keep going with your own times.
    Under the toggle: "Today that means pings at 5:00, 10:00, 3:00 and 8:00."

79. [M] (S) Warn about a stop time that does nothing.
    If keep going's stop time is before the first fresh window, say so
    instead of silently pinging once.

80. [L] (S) Presets.
    "Early bird", "Nine to five", "Night owl": one click to fill in a

81. [L] (L) Calendar awareness.
    Don't open a window on a day your calendar says you're away.

82. [L] (S) Hold keep going when the week is nearly gone.
    Above, say, 95% of the week, new windows are little use. Offer to stop

I. HELP AND WORDING
-------------------

91. [M] (S) Search in Help.
    A search box over the questions.

92. [M] (S) More questions.
    "Why is my fresh window at 10:40, not 10:00?", "Why does the ring say
    0%?", "Does Tuloy use my allowance?" (yes: 350 tokens a ping), "What
    happens at the weekly limit?", "Can I use it on two Macs?"

93. [M] (S) Rethink the word "ping".
    It's a programmer's word. Try "wake-up message" or "starter message" on
    someone who doesn't code and see which they understand first.

94. [M] (S) One name for each thing.
    The app says "fresh window", "reset", "refill" and "allowance" for
    nearly the same idea. Pick one for each and use it everywhere.

95. [M] (S) Help that opens at the right answer.
    "Fix This…" and each (?) should land on the exact question, already
    open.

96. [L] (M) Help in Filipino.
    The name is Filipino. A Tagalog translation would suit it.

97. [L] (S) A one-minute video or animation.
    The idea is easier seen than read: a day's timeline with the ping, the
    early window and the fresh one.

98. [L] (S) A glossary in Help.
    Window, fresh window, ping, keep going, week: one line each.

99. [L] (S) "What's new" after an update.
    A short list the first time a new version opens.


J. ACCESSIBILITY AND KEYBOARD
-----------------------------

100. [H] (S) Copy and paste with the keyboard.
     An app with no menu bar has no Edit menu, so Command-C may not work on
     selected text. Add the standard menus while a window is open.

101. [M] (S) Move through the sidebar with the keyboard.
     Arrow keys between screens, and Command-1 to Command-5 to jump.

102. [M] (S) Check every screen with VoiceOver.
     The ring and the steps have labels, but nothing has been listened to
     from start to finish.

103. [M] (S) Never rely on colour alone.
     Done and problem already use different symbols. Check the timeline's
     pale, solid and dashed blocks the same way.

104. [M] (S) Bigger text.
     Follow the system's text size, and make sure nothing is cut off at the
     largest setting.

105. [L] (S) Respect "Reduce motion" and "Increase contrast".

106. [L] (S) Command-W closes, Command-R pings, Command-comma opens
     Preferences, in every window.

107. [L] (S) A bigger click target on the mini window's small button.

114. [L] (S) A short tagline everywhere.

115. [L] (S) Illustrations for empty and success states.

116. [L] (S) Ring styles.
     Thin, thick, or a bar, for the menu bar and the mini window.

117. [L] (S) Tidy number formats.
     "3 h 12 min" in one place and "3:12" in another. Choose where each

118. [M] (S) A matching glyph for every state.

119. [L] (S) A proper window title bar.

L. TRUST, PRIVACY AND SAFETY
----------------------------

120. [H] (S) Protect the settings backup.
     ~/.tuloy/settings-backup.json is a copy of Claude Code's settings,
     which can hold private values. Make it readable only by you, and
     delete it a week after Connect.

121. [H] (S) Say plainly what Tuloy is.
     On the About screen and the README: an independent tool, not made or
     endorsed by Anthropic, that only times when your windows start. It
     gives you nothing beyond your plan. Link Anthropic's usage policy and
     note that they could change how windows work.

122. [M] (S) A "what Tuloy has done" list.
     Every ping, every file it changed, with times. Mostly there as Recent
     pings; this adds the file changes.

123. [M] (S) A privacy note.
     What Tuloy stores (settings and ping history, on your Mac) and what it
     sends (one message to Claude, nothing else, nowhere else).

124. [M] (S) An Uninstall button.
     Disconnect live usage, remove ~/.tuloy, turn off launch at login, and
     say what's left to drag to the Bin.

125. [M] (S) Confirm before the first automatic ping.
     Pings start the moment the schedule says so. The welcome's last page
     could say "Tuloy will send its first ping tomorrow at 5:00. OK?"

126. [L] (S) Be careful with the Claude name.
     "For Claude" in text is fine. Avoid Anthropic's logo and colours in
     the icon, so nobody takes it for an official app.

127. [L] (S) Reset everything.
     One button to put all settings back and clear history.

N. SHARING TULOY WITH OTHERS
----------------------------

132. [H] (S) Put it in git.
     The project isn't under version control yet. Start now, before the
     next big change, so anything can be undone.

133. [H] (S) Choose a licence.
     Without one, nobody else may legally use or change the code.

134. [M] (S) A version that goes up.
     It still says 0.1.0. Number each release and show it in the app.

135. [M] (S) A changelog.
     What changed in each version, in plain words.

136. [M] (M) A download page.
     One page: what it is, a screenshot, a download button, the three steps
     to start.

137. [M] (M) Automatic updates.
     "Check for Updates" in Preferences, and a quiet check once a day.

138. [M] (S) A disk image to download.
     "Drag Tuloy to Applications", like most Mac apps.

139. [M] (S) A Homebrew install.
     brew install --cask tuloy, once it's signed.

140. [M] (S) Build for Intel Macs too.
     The build is Apple silicon only. One flag makes it run on both.

141. [H] (M) Sign and notarise, so others can open it.
     With your Apple Developer account. Without it, other Macs block the
     app. Add a "make release" that does both.

142. [L] (S) A way to send feedback.
     A link in About: an email address or the project's issues page.

143. [L] (S) Not for the App Store.
     Tuloy has to run the claude command, which App Store apps may not do.
     Worth writing down so nobody spends a week finding out.


O. CODE QUALITY AND TESTING
---------------------------

144. [H] (S) Save one real ping as a test.
     The tests use ping output written from Claude Code's documentation.
     Now that real pings work, run the ping command once in Terminal, save
     what it prints, and test against the real thing.

145. [H] (M) Test the brain, not just the parts.
     The schedule, the planner and the readers are tested. What happens
     after a ping (saving, retrying, resting) is not. Let tests hand the
     app a pretend clock and a pretend Claude, and cover it.

146. [M] (M) Split up AppModel.
     One file holds settings, the loop, pings, windows and demo data: about
     500 lines. Three smaller pieces would be easier to change safely.

147. [M] (S) Run the tests on every change.
     A GitHub Actions job that runs "make test". Needs 132 first.

148. [M] (M) Compare screenshots automatically.
     The tests already draw every screen. Keep approved copies and fail the
     test when a screen changes by accident.

149. [M] (S) One place for every sentence.
     The same status is worded separately for the menu, Home and the mini
     window. Write each once, which also makes translation possible.

150. [M] (S) Get ready for translation.
     Move text into Apple's string catalogue, so 96 becomes a matter of
     filling in a table.

151. [M] (S) A code formatter and a linter.
     So style stays the same without thinking about it.

152. [L] (S) Test daylight saving and time zone changes.
     The schedule sums take care with them, but no test crosses a clock
     change.

153. [L] (S) Test the launch rules.
     First run, opened by you, started at login, mini window on: which
     windows open in each case.

154. [L] (S) Keep demo data in its own file.
     It sits inside the model. Moving it out keeps the real code shorter.

155. [L] (S) Record how long each ping takes.
     Useful for spotting a slow Claude Code, and for choosing 21's limit.
